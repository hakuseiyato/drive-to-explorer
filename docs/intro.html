Drive で開いているフォルダを、
エクスプローラーでそのまま開く。

Google ドライブ（Web）で見ている場所を、Google ドライブ デスクトップ アプリが 同期しているローカルフォルダとしてワンクリックで開きます。 パスを目で追ってたどり直す作業がなくなります。

ファイルを指定したときは、そのファイルが選択された状態で開きます。ドライブレターは環境に合わせて自動検出します。

何が変わるか

「このファイル、ローカルのどこ？」を毎回探さない

デスクトップ アプリはドライブを丸ごと同期しますが、Web 画面とエクスプローラーは 別々の世界です。フォルダ階層が深いほど、同じ場所をもう一度たどる手間が積み上がります。

これまで

手でたどり直す

  • Web のパンくずを目で読み、エクスプローラーで同じ階層を開き直す
  • 共有ドライブか マイドライブか、どちらの配下かを毎回考える
  • フォルダ名の全角や記号を打ち間違えて開けない
  • チャットで共有されたリンクは、まず Drive で開いてから探し直す
導入後

ワンクリックで着地する

  • Drive で見ている場所が、そのままエクスプローラーで開く
  • 共有ドライブ／マイドライブの判別は自動
  • ローカルパスの文字列だけコピーもできる（他ツールへの貼り付け用）
  • 共有されたリンクは、開かずに右クリックからそのまま着地できる

使い方

4 つの入口

どれも同じ解決処理を通ります。作業の流れに合う入口を選んでください。

右クリックメニュー

Drive Web でフォルダやファイルを右クリック →「フォルダ情報」→「エクスプローラーで開く」。最も確実な経路です。

ツールバーアイコン

拡張アイコンをクリックすると、Drive の階層と解決先のローカルパスを確認してから開けます。

共有されたリンク

チャットやメール、任意のページ上の Drive リンクを右クリック →「このリンクをエクスプローラーで開く」。リンクを開く必要がありません。

キーボード 任意キー

ブラウザのショートカット設定で好きなキーを割り当てられます。既定は未割当（他の拡張との衝突を避けるため）。

逆方向もできます

エクスプローラーでフォルダを右クリック →「Drive で開く」で、対応する Drive Web のフォルダを開きます。

仕組み

なぜ拡張機能だけでは足りないのか

ブラウザ拡張はサンドボックスの中で動くため、explorer.exe を直接起動できません。 そこで Windows 側に小さなプログラム（Native Messaging Host）を置き、 拡張からの依頼を受けて起動役だけを担わせています。常駐はしません。

導入

セットアップは 3 ステップ

ローカルドライブのパスを調べたり、設定ファイルを編集する必要はありません。 zip を固定パス（例: C:\Tools\drive-to-explorer\）に展開してから始めてください。

1

setup.bat を実行

ダブルクリックするだけです。Windows 側の登録、同期先ドライブの自動検出、次に選ぶフォルダのパスのコピーまで済みます。

2

ブラウザに読み込む

拡張機能ページでデベロッパーモードを ON にし、画面に表示されたフォルダを選びます。パスはコピー済みなので貼り付けるだけです。

3

再起動して Drive API を設定

ブラウザを完全終了して再起動します。続いて拡張のオプションで Drive API を設定します。多くの方は自分の OAuth クライアント ID を発行する必要があります（次の節を参照）。

対応ブラウザChrome / Edge / Brave / Vivaldi / Chromium

ローカルパスの設定初回に自動検出されます（手入力は不要）

導入前に

先に知っておいてほしいこと

ストア公開されていない個人開発のツールです。初回だけ、通常の拡張機能とは違う 手順と画面が出ます。驚かないように先に書いておきます。

ストアからは入りません

Chrome ウェブストアには公開していないため、zip を展開して「パッケージ化されていない拡張機能を読み込む」で導入します。デベロッパーモードを ON にする必要があります。

そのため、ブラウザ起動時に「デベロッパーモードの拡張機能を無効にする」という確認が出ることがあります。

OAuth クライアント ID は自分で発行します

同梱の既定クライアント ID は、同意画面を「テスト」ステータスで運用しています。テストユーザーに登録されていないアカウントではサインインできません。作者の Google Cloud プロジェクトのクォータが第三者の利用で消費されるのを避けるためです。

オプション画面の「セットアップウィザードを開く」に従えば、Cloud Console の該当ページへ直接ジャンプし、リダイレクト URI も自動でコピーされます。無料で、5 ステップです。

サインイン時に出る「このアプリは Google で確認されていません」は、審査を通していない個人開発アプリの標準的な警告です。「詳細」→「移動」で進めます。

Windows 専用です

エクスプローラーを起動する仕組みのため、macOS と Linux では動作しません。

無保証です

個人が業務の必要から作ったツールを公開しているものです。改変・再配布は自由ですが、動作の保証やサポートの約束はありません。

Drive API

サインインしなくても使えますが、一部の機能は API が必要です

サインインしない場合は Drive の画面を解析してフォルダ階層を組み立てます。 フォルダを開くだけならこれで動きます。

機能サインイン
フォルダを開いている状態からエクスプローラーで開く不要（画面解析で動作）
ファイル単体 URL からファイルを選択して開く必須
open?id= 形式のリンクを開く必須
他サイト上の Drive リンクを右クリックで開く必須
深い階層・共有ドライブの正確な解決推奨（画面解析では取りこぼす場合あり）

クライアント ID は自分で発行してください

同梱の既定クライアント ID は同意画面を「テスト」ステータスで運用しているため、 テストユーザー未登録のアカウントではサインインできません。 オプション画面の「セットアップウィザードを開く」から、自分のクライアント ID を 発行してください（無料・5 ステップ）。

権限とプライバシー

読み取るのはフォルダ名と階層だけ

Google ドライブに要求する権限

drive.metadata.readonly のみです。パスを組み立てるために フォルダ名と親子関係を参照するだけで、ファイルの中身は読みません。 書き込み権限も持ちません。

Windows 側に送るもの

ドライブレターから始まる絶対パスだけです。.. を含むパスは受け付けません。 Native Host が行うのは「そのパスが存在するかの確認」と「エクスプローラーの起動」だけで、 ファイルの読み書きはしません。

取得したフォルダ階層はブラウザのセッション内に一時保持するだけで、 開発者を含む第三者に送信することはありません。通信先は Google の API のみです。

ソースは全て公開しています

拡張機能・Windows 側のプログラム・ビルド手順のすべてが GitHub にあります。 自分でビルドして使うこともできます。上記の説明は リポジトリで検証できます。

クライアント ID は OAuth 同意画面で誰にでも見える値で、秘密情報ではありません。 本ツールはクライアント シークレットを必要としないフローを使っており、 リポジトリにも含まれていません。発行されるトークンは サインインしたあなた自身の Drive に対するものです。

制約

できないこと

項目状況
共有ドライブ名の表示 拡張の画面に共有ドライブ名が出ないことがあります。名前を返す API がより広い権限を要求するため、最小権限を優先しました。エクスプローラーは正しく開きます
ローカルに同期されていないファイル デスクトップ アプリの同期対象外のフォルダは開けません。この場合は親フォルダを開きます
Drive UI の変更 サインインしていない場合は画面解析に頼るため、Google 側の UI 変更で階層が取れなくなる可能性があります。サインインしていれば API 経由なので影響を受けません
Drive UI の言語 日本語と英語の表示を前提にしています。他の言語では画面解析側が動作しない場合があります
